# 审查回归矩阵

按业务风险而非代码行数执行，修复前先提交失败用例。

## P0：控制流与协议

- 每个新状态均覆盖创建、查询、路由、展示、人工处理、重试和重复操作；`ok` 与 `ad` 分别验证放行和处罚。
- 相关开关组合：全开、全关、单独开启、全局/单群覆盖、旧配置和非法值；关闭增强流程不得跳过旧审核。
- 含 `yield` 的 `async def` 用真实异步生成器及 `async for` 测试；mock 保持同一返回协议。
- AstrBot 工具按名称检查最终 JSON Schema；递归断言数组均有合法 `items`，不依赖声明索引。

## P0：关联、权限与远程动作

- 同群同用户重复文本、多条 pending、0/1/多候选；只有唯一候选绑定，否则人工确认。
- 指令、LLM、WebUI、审核联动调用同一动作原语；测试群主、管理员、普通成员、未绑定 Web 用户、目标为管理员/群主/Bot 的组合。
- 平台成功、`None`、异常、超时、限速、消息过期、部分成功、重复点击和并发确认；底层未明确成功不得回执成功。

## P1：外部依赖与审核输入

- 搜索工具缺失、空/畸形返回、提示注入、单次/总超时、取消、复审失败均转人工并记录原因。
- OneBot 纯文字、纯回复、回复+文字、多层引用、加群问题+答案；协议附加内容不得作为用户输入匹配。
- 图片占位符、相同文本刷屏、连续短消息拼接、跨群/跨用户/非文本打断。

## P2：同步与部署

- push/pull、旧客户端/服务端、字段 allowlist、冲突、部分失败、重试幂等、并发锁和审计闭环。
- 重复插件目录、缺失/损坏 metadata、权限、符号链接、大小写、宿主加载时序和启动性能。

“全量通过”只作为一层证据；真实宿主、平台和外部服务冒烟测试不能替代本地确定性断言。
