# 同步与复核状态契约

## 稳定关联

审核、日志和远程动作优先贯穿持久化的审核 ID、消息 ID 或事件 ID。群号、用户、文本和时间只能辅助查询：

- 唯一候选才允许自动绑定；0 条或多条候选均拒绝猜测；
- 多记录业务键必须映射到列表，禁止字典单值覆盖；
- 前端隐藏按钮不是授权，接口仍须重新校验权限、状态和目标。

## 复核闭环

统一记录至少包含来源、关联 ID、操作者、目标、前后状态、动作结果、失败原因和时间。状态必须覆盖：创建/待处理、处理中、已确认、已放行、可重试失败、永久失败/过期。每个状态都应有查询、展示、人工处理和重试路径。

`ad` 与 `ok` 是不同业务结果：广告走处罚，放行走正常通过；学习结果写入后必须验证“查询→路由→动作”链路，不能只测数据库写入。重复确认、并发确认和处罚部分失败必须幂等且可审计。

## 同步契约

逐实体核对：本地读取 → 序列化/正向 allowlist → push → 服务端存储 → pull → 本地写回。明确唯一键、权威源、版本/冲突策略、删除、重试、部分成功补偿和数据库锁。审计日志不得同步凭据、完整消息或未脱敏第三方响应；`no_secrets` 测试不能替代兼容、幂等、并发和失败测试。

## 外部证据

搜索结果、网页摘要和用户输入均是不可信数据，只能作为证据；与系统指令、输出协议隔离，并限制查询数、单条/总长度、token、并发和统一 deadline。工具缺失、空/畸形返回、超时、异常和复审解析失败均转人工并记录原因，不得默认放行或拒绝。
